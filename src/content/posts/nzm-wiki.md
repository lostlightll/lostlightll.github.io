[逆战未来 Wiki](https://lostlightll.github.io/nzm-wiki/) 是我在维护的《逆战未来》非官方资料站，武器数据、插件效果、塔防图鉴都有，也写一些机制说明和攻略。源码在 [lostlightll/nzm-wiki](https://github.com/lostlightll/nzm-wiki)。

## 从 Fork 开始

项目最早是 [@qiekn](https://github.com/qiekn) 写的 [nzm-wiki](https://github.com/qiekn/nzm-wiki)。原项目更新得比较慢，部分枪械数据也不够清楚，2026 年 5 月底我就 fork 了一份，按自己的需求改。

Fork 之后第一个大改动是重构武器数据管线，直接对接游戏解包数据。后面几个月基本都在干同一件事，把手写的数字换成有出处的数字。

> 写这篇的时候仓库有大约 940 个提交，原作者的占 357 个，剩下的都是 fork 之后攒的。

现在站里大概有这些。

| 板块 | 规模 |
| --- | --- |
| 猎场武器 | 121 篇 |
| 塔防陷阱 | 28 篇 |
| 机制与攻略文章 | 20 篇 |
| 其他 | 插件、超限、赛季天赋、原点、Boss、敌人、配装、乘区 |

技术栈是 Next.js 16 + React 19 + TypeScript + Tailwind CSS v4 + MDX，静态导出后放在 GitHub Pages 上。

## 把 Wiki 当数据库

游戏 wiki 最常见的毛病就两个。数字抄错了没人发现，版本更新了旧数字还挂在页面上。

所以这个项目里的数值不直接写死在 MDX 里，都要走一遍管线。

1. **解包**，从游戏资源里读出原始配置。
2. **Lock**，把审过的原始值锁进仓库，比如 `weapon-data-lock.json`、`num-modifier-lock.json`。
3. **Project**，从 Lock 生成页面实际用的派生数据。
4. **Check**，校验页面引用的每个数值都能在 Lock 里找到。

平时改完内容跑一下 `pnpm sync` 就行。它会依次更新超限关联、属性与乘区索引、武器技能索引、搜索索引和站点地图，哪一步校验没过就停在哪一步。

## 先统一说法

做到乘区和属性索引那会儿，最麻烦的是怎么叫。

同样一个「+10%」，可能是原表里的一行配置，也可能是玩家看到的一条效果，还可能是伤害公式里的一个乘区。几种东西混着叫，文档和代码一起乱。后来仓库里专门放了一份 `CONTEXT.md` 定术语，下面摘几条。

| 叫法 | 指什么 |
| --- | --- |
| Num Modifier 行 | 原始配置里的一条记录 |
| 属性类型 | 改的是什么属性，比如暴击率、移动速度 |
| Modifier 效果 | 这条记录实际改了哪个属性、改了多少 |
| 伤害通道 | 能进最终伤害公式的那部分效果 |

每个词后面还附了「别这么叫」的反例。词定下来以后，索引和计算器写起来顺手多了。
